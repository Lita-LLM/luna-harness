## 1. Gemini CLI (Google)

**Что это:** открытый терминальный агент Google, `gemini`, TypeScript / Node.js ≥20, **Apache-2.0**. Официальный сайт и README: [google-gemini.github.io/gemini-cli](https://google-gemini.github.io/gemini-cli/) — на 2026-10-31 там по-прежнему заявлены free tier 60 req/min, 1000 req/day с личным Google-аккаунтом, Gemini 2.5 Pro, контекст 1M, встроенные инструменты и MCP.

**Что с ним стало в 2026 — главное:**
- По официальному анонсу Google Developers Blog «An important update: Transitioning Gemini CLI to Antigravity CLI» от **19 мая 2026** (заголовок и дата — из выдачи официального блога `developers.googleblog.com`, полный текст блога в этом проходе повторно не открывался из-за 429, поэтому детали перехода сверены по официальному репозиторию преемника, см. §9): для **free / Google AI Pro / Ultra индивидуальных** пользователей Gemini CLI и Gemini Code Assist IDE extensions **перестали обслуживать запросы 18 июня 2026**.
- **Не умерли полностью:** enterprise (Gemini Code Assist Standard/Enterprise) и платные Gemini API keys — carve-out, доступ сохраняется. Репозиторий Apache-2.0 не удалён.
- Преемник для индивидов — **Antigravity CLI (`agy`)**, см. §9.

**Уникальные идеи (относительно тройки):**
1. **Встроенный Google Search grounding как штатный инструмент** агента, а не MCP-надстройка — прямо в списке built-in tools на официальном сайте.
2. **Официальный GitHub Action как часть продукта:** PR-ревью, issue triage и `@gemini-cli` в issues/PR — на официальном сайте, раздел GitHub Integration.
3. **Медиа-генерация через MCP из коробки в примерах:** Imagen / Veo / Lyria как демонстрируемый сценарий расширений — там же.
4. **GEMINI.md + conversation checkpointing + token caching** как документированный набор именно этого CLI — есть в официальной документации, но как *сочетание с бесплатным 1M-контекстом* это была его визитная карточка до ухода в Antigravity.

## 2. Aider

**Что это:** AI pair programming в терминале, Python, **Apache-2.0** (лицензия — по карточке проекта на GitHub/PyPI; в открытых в этом проходе страницах docs она отдельно не показана — помечаю как не перепроверенную по docs). Документация: [aider.chat/docs](https://aider.chat/docs/) — на 2026-10-31.

**Уникальные идеи:**
1. **Repo Map с графовым ранжированием.** Не просто список файлов: карта всего git-репо (файлы + ключевые классы/функции + сигнатуры), обрезанная под токен-бюджет (`--map-tokens`, по умолчанию 1k) алгоритмом ранжирования по графу зависимостей файл→файл, с динамическим расширением, когда в чате нет файлов. Источник: [aider.chat/docs/repomap.html](https://aider.chat/docs/repomap.html).
2. **Git-нативность как откат, а не просто коммиты.** Каждое изменение — отдельный коммит с описательным сообщением; грязные файлы перед правкой коммитятся отдельно, чтобы не смешивать работу человека и AI; `(aider)` в author/committer для атрибуции и статистики «aider wrote xx%»; `/undo`, `/diff`, `/commit`, `/git` прямо из чата. Источник: [aider.chat/docs/git.html](https://aider.chat/docs/git.html).
3. **Architect/Editor — двухмодельный режим как штатный chat mode.** Сильная reasoning-модель проектирует, вторая (editor-модель, со своими edit-форматами `editor-diff`/`editor-whole`) переводит замысел в точные правки файлов. Рядом — режимы `code / ask / help`, переключаемые и «липко» (`/chat-mode`), и на одно сообщение (`/ask ...`). Источник: [aider.chat/docs/usage/modes.html](https://aider.chat/docs/usage/modes.html).
4. **Watch-режим по комментариям в редакторе и voice-to-code** — вынесены в отдельные разделы официальной документации ([aider.chat/docs](https://aider.chat/docs/): «Aider in your IDE — watch files и AI-комментарии», «Voice-to-code»). Детальные подстраницы в этом проходе не открывались из-за 429 — идея зафиксирована по оглавлению официальной docs, детали — **не перепроверены**.
5. **Edit formats и LLM Leaderboards как часть продукта:** aider сам публикует бенчмарки правок/рефакторинга разных моделей — раздел «Aider LLM Leaderboards» в официальной docs.

## 3. Crush (Charm)

**Что это:** терминальный агент от Charm (команда Bubble Tea / Glamour), **Go, один бинарь**, репозиторий создан 2025-05-21. Лицензия в карточке GitHub на 2026-10-31 отображается как `Other (NOASSERTION)`; по вторичным сводкам и `LICENSE.md` в репо это **FSL-1.1-MIT (source-available, конвертируется в MIT через 2 года)** — трактовать именно как source-available, а не OSI open source, пока не сверено по тексту `LICENSE.md` построчно. Источник: [github.com/charmbracelet/crush](https://github.com/charmbracelet/crush).
Происхождение: форк/продолжение ранней ветки, briefly связанной с именем OpenCode, ребрендированной Charm в Crush; нынешний OpenCode — отдельный проект. (Этот исторический пункт — по вторичным источникам, в README в открытом фрагменте не подтверждён — **помечаю как неподтверждённый по первоисточнику в этом проходе**.)

**Уникальные идеи:**
1. **LSP как источник контекста, «как у разработчика в редакторе».** Не grep-only: Crush подключает Language Server Protocol для дополнительной кодовой осведомлённости — прямо в Features README.
2. **Смена модели mid-session без потери контекста + мульти-сессии на проект** как первоклассные фичи (Features: Multi-Model / Flexible / Session-Based) — README на GitHub.
3. **Конфиг — это Bash: `crushrc`.** Встроенный Bash-интерпретатор, поэтому конфиг одинаков и на Windows: `provider add`, `model add`, `permissions allow`, `mcp add ... $(op read ...)` с секретами из 1Password прямо в конфиге; приоритет `./.crushrc` → `./crushrc` → `~/.config/crush/crushrc`. Старый JSON-конфиг — deprecated, но поддерживается. Источник: README, раздел Configuration, там же.
4. **Catwalk — отдельный открытый каталог моделей/провайдеров**, поддерживаемый сообществом, а не захардкоженный список внутри бинаря; плюс собственный провайдер **Charm Hyper** (подписка, zero data retention по заявлению Charm) — README, разделы Getting Started / By the Way.
5. **Покрытие платформ шире тройки:** macOS, Linux, Windows (PowerShell и WSL), **Android, FreeBSD, OpenBSD, NetBSD, illumos** — один Go-бинарь, включая prebuilt android-arm64 (Features / Installation в README).

## 4. Goose (Block → Agentic AI Foundation)

**Что это:** универсальный агент **не только для кода** — desktop app + CLI + API, **Rust, Apache-2.0**. На 2026-10-31 репозиторий уже **не `block/goose`, а [github.com/aaif-goose/goose](https://github.com/aaif-goose/goose)**: goose передан в Agentic AI Foundation (AAIF) при Linux Foundation, доки переехали на goose-docs.ai (старые block.github.io ссылки редиректят/устарели). 15+ провайдеров, подписки Claude/ChatGPT/Gemini — через ACP.

**Уникальные идеи:**
1. **Recipes — переиспользуемые YAML/JSON-конфиги агента как артефакт для шеринга.** Пакет из `instructions + prompt + extensions + parameters + response (JSON-schema) + retry + sub_recipes`: `goose run --recipe x.yaml --params k=v`, валидация `goose recipe validate`, запуск по cron (`goose schedule add --cron ...`). Источник: [block.github.io/goose/docs/guides/recipes/recipe-reference](https://block.github.io/goose/docs/guides/recipes/recipe-reference) (на 2026-10-31 страница ещё отдавалась; актуальный канон — goose-docs.ai).
2. **Extensions = только MCP-серверы, включая встроенные и platform-extensions.** В рецептах типы `builtin / stdio / streamable_http / platform`; особая platform-extension **Summon** даёт инструменты `delegate`/`load` для субагентов, а рецепты с `sub_recipes` получают её автоматически — та же страница Recipe Reference.
3. **Headless/automation — первоклассный режим, а не флаг для галочки:** structured output через `response.json_schema`, allowlist расширений (`GOOSE_ALLOWLIST`), режимы разрешений через env (`GOOSE_MODE=auto`). Источник: официальная страница Headless Mode в docs goose (block.github.io/goose/docs/tutorials/headless-goose, на 2026-10-31).
4. **Custom Distributions:** можно собрать **свой дистрибутив goose** с предконфигом провайдеров, расширений и брендинга — ссылка Custom Distributions прямо в README нового репо.
5. **Позиционирование «general-purpose»:** research, writing, data analysis, automation — агент для любой работы на своей машине, а не только кодинг-харнесс (README aaif-goose/goose).

## 5. Amp (бывший Sourcegraph, ныне Amp Frontier Corporation)

**Что это:** проприетарный мульти-модельный агент: CLI + web + macOS/iOS/Android, **закрытый исходник, лицензии open source нет**. Изначально проект Sourcegraph, публично с мая 2025; в декабре 2025 выделен в независимую Amp Frontier Corporation (этот факт — по вторичным сводкам на основе официального Chronicle, в открытом в этом проходе manual прямо не расписан — помечаю как частично подтверждённый). Официальный manual: [ampcode.com/manual](https://ampcode.com/manual) — на 2026-10-31 оттуда: «built for the frontier», мульти-модель без ручного выбора, Orbs, Threads.

**Уникальные идеи:**
1. **Threads как серверные, шаримые, кросс-девайсные объекты работы, а не локальный чат.** Тред сохраняется, им делятся (видимости public/unlisted/workspace/private — по вторичным описаниям manual; в открытом фрагменте manual подтверждено «save and share your interactions»), его продолжают с другого устройства/человека. Источник: [ampcode.com/manual](https://ampcode.com/manual).
2. **Handoff вместо compaction.** Amp **убрал** `/compact`: вместо лосси-сжатия истории `/handoff <цель>` создаёт **новый тред**, упаковав только релевантный контекст + черновик промпта + список файлов на ревью пользователя. Оригинал не трогается. (Механика — по официальным новостям Amp, пересказанным в Chronicle/новостных сводках; прямая страница handoff в этом проходе не открывалась из-за 429 — идея подтверждена несколькими независимыми пересказами официального анонса, текст первоисточника построчно **не сверен**.)
3. **Oracle и Librarian — ролевые субагенты на других моделях.** Oracle — «второе мнение» сильной reasoning-модели для дебага/ревью/плана (в Chronicle: «GPT-5.4 is now Amp's oracle», 5 марта 2026; «GPT-5 Oracle», 1 окт. 2025). Librarian — субагент поиска по **чужим/удалённым репозиториям GitHub** и зависимостям, а не только по локальному коду (Chronicle: «The Librarian — A new subagent for searching code on GitHub», 20 окт. 2025). Источник списка: [ampcode.com/chronicle](https://ampcode.com/chronicle).
4. **Orbs — облачная машина на каждый тред.** Manual: «Machines that Amp creates per thread, with your code, tools, and plugins already set up. Send a prompt, close your laptop, and the agent keeps working». Плюс координатор **Puck**, который запускает и координирует агентов — упомянут прямо в manual.
5. **Модель абстрагирована, выбирается «усилие», а не модель.** Философия: Amp сам подбирает модель под подзадачу (main / oracle / librarian / дешёвые служебные), пользователь не обязан выбирать провайдера. В 2026 это эволюционировало в режимы-«dial» (low/medium/high/ultra по вторичным сводкам офиц. docs — построчно не сверено).

## 6. Cline / Roo Code / Kilo Code (VS Code-семейство)

Общая генеалогия: **Cline (2024, оригинал) → Roo Code (форк Cline) → Kilo Code (форк Roo)**. Все — TypeScript, VS Code-расширения, позже обросли CLI.

### 6a. Cline

**Что это:** VS Code-агент, **Apache-2.0**, плюс CLI/JetBrains/desktop/SDK. Доки: [docs.cline.bot](https://docs.cline.bot/core-workflows/plan-and-act).

**Уникальные идеи:**
1. **Plan / Act как жёсткое разделение «думать / делать» с разными моделями.** В Plan агент только читает и обсуждает, **не может** менять файлы и выполнять команды; в Act контекст планирования сохраняется целиком. Для каждого режима — **своя модель** (сильная на план, быстрая на исполнение). Источник: [docs.cline.bot/core-workflows/plan-and-act](https://docs.cline.bot/core-workflows/plan-and-act).
2. **Checkpoints на теневом Git-репозитории (shadow git), отдельно от истории проекта.** После каждого tool use — снимок в отдельный shadow repo, не трогая основной git; восстанавливать можно **раздельно**: только файлы / только задачу (историю сообщений) / файлы+задачу. Это делает безопасным auto-approve. Источник: [docs.cline.bot/core-workflows/checkpoints](https://docs.cline.bot/core-workflows/checkpoints) (обновлено 2026-02-15 на самой странице).
3. **MCP Marketplace внутри расширения** и `/deep-planning` как отдельный проработанный сценарий планирования — по оглавлению официальной docs Cline (детали в этом проходе не открывались).

### 6b. Roo Code — закрыт

**Что это:** форк Cline, **Apache-2.0, TypeScript**. На 2026-10-31 репозиторий **архивирован**: [github.com/RooCodeInc/Roo-Code](https://github.com/RooCodeInc/Roo-Code) — в README прямо: «The Roo Code Extension was shut down on May 15th», альтернативы — ZooCode (комьюнити-форк) и Cline.

**Чем отличался (исторически, идеи переехали в Kilo/ZooCode):**
1. **Режимы как «команда разработчиков»:** Code / Architect / Ask / Debug + **Custom Modes** со своими инструментами, правилами и моделью на режим — README архива, раздел Modes.
2. **Orchestrator / Boomerang Tasks:** режим-оркестратор разбивал большую задачу на подзадачи и делегировал их другим режимам, собирая результат обратно («бумеранг»). В новом Kilo этот режим **deprecated** (см. ниже) — как именованная фича Roo она важна именно как источник идеи.
3. **Memory Bank:** структурированные markdown-файлы памяти проекта в репо (`.roo/.../memory-bank`) — в Kilo при миграции заменён на `AGENTS.md` (см. миграционный гайд Kilo).

### 6c. Kilo Code

**Что это:** наследник Roo, в 2026 **пересобран на OpenCode server** (общее ядро VS Code + CLI + Cloud Agents, GA новой версии — 2 апреля 2026 по официальному «What's New»). Лицензия нового ядра — MIT (OpenCode-основа) / legacy-код Apache-2.0 — по сравнительным сводкам; по официальным страницам Kilo в этом проходе лицензия построчно не сверена. Источники: [kilo.ai/docs/code-with-ai/platforms/vscode/whats-new](https://kilo.ai/docs/code-with-ai/platforms/vscode/whats-new), [kilo.ai/articles/roo-to-kilo-migration-guide](https://kilo.ai/articles/roo-to-kilo-migration-guide).

**Уникальные идеи:**
1. **Modes → Agents + Sticky / Auto Models.** Режимы переименованы в агентов (Code/Plan/Ask/Debug + кастомные агенты markdown+YAML frontmatter); модель можно **закрепить за агентом (Sticky Models)** или отдать автовыбору (Auto Models) — миграционный гайд Kilo.
2. **Agent Manager: параллельные сессии в git worktree из коробки в редакторе.** Панель управления: несколько топ-левел сессий, каждая в изолированном worktree (`.kilo/worktrees/`) со своим терминалом, веткой и setup-скриптами; **Multi-Version Mode — до 4 параллельных реализаций одного промпта** в разных worktree для сравнения; импорт сессии из ветки/PR URL. Источник: [kilo.ai/docs/automate/agent-manager](https://kilo.ai/docs/automate/agent-manager).
3. **Kilo Swarm — общая «доска» между сессией и её потомками:** инструменты `board_post`/`board_read` для обмена находками между task-субагентами внутри одной сессии (Agent Manager Workflows в официальной docs Kilo; страница в этом проходе — по поисковой выдаче официального сайта, построчно не открывалась).
4. **Оркестратор без оркестратора:** отдельный Orchestrator mode упразднён — любой агент с полным доступом к инструментам сам делегирует через `task`. Плюс snapshots вместо checkpoints Roo: git-снимки в `~/.local/share/kilo/snapshot/`, откат по сообщению — What's New / миграционный гайд.

## 7. Cursor CLI (`cursor-agent` / `agent`)

**Что это:** тот же агент, что и в редакторе Cursor, но как терминальный бинарь `agent`; **проприетарный**, установка `curl https://cursor.com/install -fsS | bash`. Доки: [cursor.com/docs/cli/overview](https://cursor.com/docs/cli/overview), [cursor.com/docs/cli/using](https://cursor.com/docs/cli/using) — на 2026-10-31.

**Чем отличается от редактора (уникальные идеи):**
1. **Это не урезанный редактор, а тот же агент с теми же режимами/правилами/MCP:** режимы Agent/Plan/Ask (`--mode`, `Shift+Tab`), правила `.cursor/rules` и `mcp.json` подхватываются из конфигурации редактора автоматически — CLI Overview / Using.
2. **ACP-сервер из коробки:** `agent acp` запускает Cursor CLI как ACP (Agent Client Protocol) сервер по stdio/JSON-RPC для кастомных клиентских интеграций — Using Agent in CLI.
3. **Облачный хендофф одной буквой:** префикс `&` к любому сообщению отправляет разговор в **Cloud Agent**, который продолжает без локальной машины; подобрать результат — на web/mobile (cursor.com/agents). Плюс `-w/--worktree [name]` — работа в отдельном git worktree под `~/.cursor/worktrees/...` и `agent persist` — постоянные сессии на удалённом хосте (persist — по changelog CLI, в открытых страницах в этом проходе прямо не показан, помечаю как **по changelog, не по overview**).
4. **Headless/print для CI:** `-p/--print`, `--resume/--continue`, `agent ls` для прошлых чатов; безопасный sudo-промпт по secure IPC, **пароль модель не видит** — CLI Overview (последний пункт — прямо в overview на 2026-10-31).
5. **Разделение с редактором по сути одно:** нет GUI-диффов/табов редактора; всё остальное (субагенты `.cursor/agents/`, skills, hooks) — общее ядро, поэтому «уникальность» Cursor CLI — именно в мосте терминал ↔ облако ↔ редактор, а не в отдельном агентном движке.

## 8. Grok CLI — на самом деле Grok Build (xAI / SpaceXAI)

**Статус на 2026-10-31 — честно и осторожно:**
- **Официальный продукт ЕСТЬ.** Называется не «Grok CLI», а **Grok Build**, бинарь — `grok`. Вокруг много неофициальных «grok-cli» (самый известный — community `superagent-ai/grok-cli`, **не аффилирован с xAI**); путать нельзя.
- Первоисточник: [github.com/xai-org/grok-build](https://github.com/xai-org/grok-build) — репозиторий создан **2026-07-14** (публичная выкладка исходников), **Rust, Apache-2.0** для first-party кода, «SpaceXAI's terminal-based AI coding agent… full-screen TUI… headlessly for scripting/CI, or embedded in editors via ACP», исходники периодически синхронизируются из внутреннего монорепо, внешние контрибуции **не принимаются** (`CONTRIBUTING.md`).
- Запуск как продукта: early beta — май 2026 для SuperGrok / X Premium+ (по вторичным сводкам официальных анонсов; на странице репо дата запуска не указана — **не утверждаю дату по первоисточнику в этом проходе**). Доступ — по подписке SuperGrok / X Premium+ или `XAI_API_KEY`, не бесплатно.

**Уникальные / примечательные идеи:**
1. **Открытый харнесс при закрытой модели, выложенный как срез монорепо:** ~полный Rust-workspace агента (TUI `xai-grok-pager`, runtime `xai-grok-shell`, tools, workspace с checkpoints) с `SOURCE_REV` — файлом точного коммита монорепо. В `THIRD-PARTY-NOTICES` честно указаны **in-tree порты инструментов из openai/codex и sst/opencode** — README репо.
2. **Полноэкранный mouse-interactive TUI как основной интерфейс**, а не построчный REPL, при тех же headless (`grok -p`) и ACP режимах — README.
3. Документация вынесена и в онлайн (docs.x.ai/build/overview — ссылка из README), и **внутрь репо** (`crates/codegen/xai-grok-pager/docs/user-guide/`: конфигурация, MCP, skills, plugins, hooks, sandboxing) — то есть user guide версионируется вместе с кодом среза.

Иных идей, достоверно отсутствующих у тройки (worktree-субагенты, workflows на много параллельных агентов и т.п.), по открытому первоисточнику в этом проходе **не подтверждаю** — они встречаются во вторичных обзорах, построчная сверка с docs.x.ai не выполнена из-за лимита браузера.

## 9. Новинки и перерождения 2025–2026

### 9a. Antigravity CLI (`agy`, Google) — преемник Gemini CLI, 2026

**Что это:** терминальный клиент платформы Google Antigravity, **один Go-бинарь `agy`**, закрытый исходник (в репо — README, changelog, issues; LICENSE в карточке репо на 2026-10-31 не показан). Репозиторий создан 2026-05-13: [github.com/google-antigravity/antigravity-cli](https://github.com/google-antigravity/antigravity-cli). Установка: `curl -fsSL https://antigravity.google/cli/install.sh | bash`.

**Уникальные идеи:**
1. **Единое ядро на 4 поверхности:** Antigravity 2.0 (GUI), Antigravity CLI, Antigravity SDK, Antigravity IDE делят **один Shared Core Agent Engine**, общие настройки/разрешения синхронизируются двунаправленно, а терминальную сессию можно **экспортировать в GUI и продолжить там** — README репо, раздел Integration.
2. **Оптимизация под SSH/remote и клавиатуру** как заявленная цель CLI-поверхности (в отличие от GUI — «comprehensiveness, visual orchestration»), аутентификация через системный keyring, для SSH — печать auth URL — README.
3. **Наследование Gemini CLI без 1:1 паритета, честно заявленное Google:** Skills, Hooks, Subagents и Extensions (теперь plugins) перенесены, плюс асинхронные мультиагентные фоновые воркфлоу (по анонсу перехода; в README репо этот список прямо не расписан — помечаю как по официальному анонсу, пересказанному во вторичных источниках).

### 9b. Mistral Vibe (Mistral AI) — декабрь 2025, активно развивался весь 2026

**Что это:** **Python 3.12+, Apache-2.0**, репозиторий создан **2025-12-08**: [github.com/mistralai/mistral-vibe](https://github.com/mistralai/mistral-vibe) — «Minimal CLI coding agent by Mistral», ставится `uv tool install mistral-vibe` / `pip install mistral-vibe`, модели Mistral (Devstral / Medium и др.).

**Уникальные / примечательные идеи:**
1. **Профили агентов = пресеты разрешений, а не ролей:** встроенные `ask` (одобрение на всё), `accept-edits` (по умолчанию, авто-одобрение только правок файлов), `auto-approve`; кастомные агенты — файлами в `~/.vibe/agents/` и `.vibe/agents/`, субагенты — тем же механизмом с `agent_type = "subagent"` — README репо.
2. **Интерактивный `ask_user_question` как инструмент агента:** агент сам задаёт уточняющие вопросы с 2–4 вариантами + «Other», несколько вопросов — вкладками — README, раздел Interactive User Questions.
3. **Voice Mode и экспериментальные серверные режимы в CLI:** голосовой ввод, `--agent-socket` (sandboxed sessions по протоколу) и `vibe run-server` («many runs in one process», experimental) — оглавление README; также `vibe-acp` для ACP-интеграций (Zed/VS Code/JetBrains).

### 9c. Pi (Mario Zechner / Earendil) — минимализм как идеология

**Что это:** **TypeScript / Node ≥22.19, MIT**, монорепо создано 2025-08-09, ныне [github.com/earendil-works/pi](https://github.com/earendil-works/pi) (ранее `badlogic/pi-mono`). На 2026-10-31 — один из самых звёздных харнессов в подборке по карточке GitHub.

**Уникальные идеи:**
1. **Сознательный отказ от фич тройки:** README прямо — «ships with powerful defaults but **skips features like sub-agents and plan mode**. Ask Pi to build what you want, or install a package that does it your way». Ядро — минимальный агентный цикл + инструменты чтения/записи/правок/bash (состав «ровно 4 инструмента» — по официальному блогу автора, в README в открытом фрагменте список не расписан).
2. **Саморасширяемость пакетами:** extensions, skills, prompt templates, themes бандлятся как **Pi packages** и шарятся через npm/git; есть RPC-режим и TypeScript SDK (`pi-ai` — единый мульти-провайдерный LLM API, `pi-agent-core`, `pi-tui` с дифференциальным рендером, `pi-durable`) — README, таблица Packages.
3. **Честный YOLO по умолчанию в вопросах безопасности:** встроенной permission-системы **нет**, агент работает с правами запустившего пользователя; изоляция — только внешней контейнеризацией, для которой docs дают 3 паттерна (Gondolin micro-VM extension, plain Docker, OpenShell) — README, раздел Permissions & Containerization.

### 9d. Прочее подтверждённое одной строкой

- **Qwen Code / ZCode / MiMo Code / MiniMax Code:** волна открытых CLI от китайских лабораторий в 2026 (Alibaba, Z.ai, Xiaomi, MiniMax) — упоминаю только как явление по вторичным сводкам; по первоисточникам в этом проходе **не проверены**, в сводный список идей не включены.
