# Веха 0 — каркас и рендерер

Закрыта исполнителем 31.10.2026 (ветка `zadacha-01`). Агента и моделей пока нет — это фундамент: пакет, ядро, собственный терминальный рендерер, заставка, doctor, замеры.

## Что готово

- **Пакет `luna/`** (Python 3.10+, только стандартная библиотека, сторонних пакетов нет): `__main__` с командами `doctor | try | settings | set | --version`; без аргументов — полноэкранный режим. `--version` и `doctor` рендерер не импортируют (проверено тестом).
- **Ядро** — перенесено из Бендера по правилам docs/research/БЕНДЕР.md (строка-источник с коммитом в каждом модуле): шина событий, HumanError, ULID, даты, пути, pathutil, атомарная запись fsutil, json5, run_lock (вторая копия на тех же данных получает понятный отказ). Раскладка данных — `~/.luna` (переопределяется `LUNA_HOME`).
- **Настройки** (`core/settings.py`) — компактная версия идеи Бендера: схема в коде (ключ, тип, умолчание, описание, допустимые значения), слои умолчания → `~/.luna/settings.json` → `./.luna/settings.json`, незнакомые поля файлов сохраняются при записи, запись атомарная, изменение публикует `settings.changed` на шине. Схема вехи: `ui.color`, `ui.unicode`, `ui.emoji` (добавлена раундом 2 ревью: auto — на Windows без Windows Terminal выключены, on, off), `ui.animations`, `ui.splash`, `ui.theme`.
- **Рендерер** (`luna/ui/`): терминал (альтернативный экран, raw-режим, восстановление при любом выходе — проверено выходом, исключением пути Ctrl+C и SIGTERM), определение возможностей (truecolor/256/16/mono, юникод; `NO_COLOR`, `COLORTERM`, `WT_SESSION`, настройки перекрывают), буфер ячеек с двойной буферизацией и выводом только изменившихся ячеек одной записью на кадр, ширина CJK/эмодзи, градиенты и деградация цвета, ввод (клавиши, модификаторы, мышь SGR 1006, bracketed paste, resize; одиночный Esc — по тайм-ауту 50 мс), планировщик анимаций до 30 кадр/с — в простое процесс спит в блокирующем ожидании ввода, опросов нет. После ревью: ширине глифов терминала рендерер не доверяет — после каждого широкого символа курсор ставится заново абсолютной координатой (у ConPTY своя ширина эмодзи, относительное продвижение расползалось по спану), а ширины своих глифов (фазы луны, брайлевский спиннер) зафиксированы явной таблицей в `ui/width.py`. Раунд 2 ревью показал предел якорей: ConPTY пересобирает поток для терминала и переписывает сами координаты, поэтому эмодзи стали настройкой `ui.emoji`, а без них интерфейс рисует **узкие фазы шириной 1** (`○◔◑◕●◕◐◔` — у каждого `east_asian_width` не W/F, проверено тестом) и узкий спиннер из полукругов; ASCII-набор остался третьим уровнем для `ui.unicode=off`. Режим глифов — одно понятие `Caps.glyph_mode` (emoji | narrow | ascii) для заставки, строки состояния, витрины и спиннера.
- **Заставка**: градиентное небо со сканлайнами, мерцающие звёзды, восход луны по фазам, «Л У Н А П А Р К» неоновым градиентом, случайная фраза, в углу — время старта до первого кадра. ~1,2 с, любая клавиша пропускает, Ctrl+C выходит совсем.
- **Минимальный экран**: ввод с редактированием и вставкой, эхо с пометкой «агент появится в следующей вехе», по Enter спиннер из легендарных фраз крутится 2 с, строка состояния с фазой луны (= заполненность «контекста») и часами. Экран получает ввод только событиями шины (`ui.key`/`ui.mouse`/`ui.paste` → подписчик), сообщения уходят на шину как `chat.message`.
- **`luna doctor`**: Python ≥ 3.10, ОС, терминал и возможности (включая строку «Эмодзи»: включены ли и почему — WT_SESSION, ConPTY-хост, настройка), доступность `LUNA_HOME` и проекта на запись, источники настроек, подсказки. Все команды с первого вызова `main()` пишут в UTF-8: потоки переконфигурируются в точке входа, а не только в полноэкранном Terminal, — иначе вывод в пайп на Windows падал на ✓/✗.
- **`luna try render | splash | measure`** — витрина рендерера (палитра, градиенты, деградация всеми уровнями рядом, фазы, линейка ширины, последнее событие ввода), заставка отдельно, замеры таблицей и `--json`.

## Замеры

Машина: Linux 7.0.0-39 (x86_64, AMD EPYC 9D25, 4 vCPU, ВМ исполнителя), Python 3.12.3, терминал — псевдотерминал 80×24 (TERM=xterm-256color, COLORTERM=truecolor). Команда: `luna try measure`.

| что | цель (ПЛАН §2) | замер |
|---|---|---|
| старт до первого кадра | ≤ 200 мс | **111 мс** (медиана 7 запусков: 162, 111, 112, 110, 115, 107, 104) |
| память в простое | ≤ 40 МБ | **22,9 МБ** RSS |
| ЦП в простое за 10 с | ≈ 0 % | **0,0 %** |
| код пакета `luna/` | ≤ 10 МБ | **0,13 МБ** |
| старт / память / ЦП на Windows | те же цели | **замер не выполнен**: механизм реализован после ревью (новая консоль + метка первого кадра), живой Windows в окружении исполнителя нет — цифры ждём с машины тимлида, выдумывать не стали |

Первый запуск в серии (162 мс) — холодный кэш ФС; медиана честнее. Все цели вехи достигнуты на этой машине. Повторный замер после правок по РЕВЬЮ-01 (та же ВМ): старт — медиана 104 мс (113, 103, 103, 104, 103, 120, 106), память 22,8 МБ, ЦП 0,0 % — регрессий нет.

## Как проверялось

- `python -m unittest -q` — 54 теста, зелёные (37 в вехе + 10 по раунду 1 РЕВЬЮ-01 + 7 по раунду 2): шина и переполнение очереди, ULID, атомарная запись, json5, run_lock; слои настроек и сохранение незнакомых полей; ширина символов (включая явную таблицу своих глифов и ширину 1 каждой узкой фазы), градиенты и деградация, фазы луны тремя наборами, разбор клавиш/мыши/вставки (включая разрезанную последовательность и Esc по тайм-ауту), дифф буфера (только изменения, одна запись на кадр, широкий символ, якорь курсора после широкого символа, обновление в колонке 0 абсолютной координатой), определение возможностей (смоделированная Windows-кодовая страница 65001 при TERM=linux; эмодзи в auto: ConPTY-хост против WT_SESSION, настройка ui.emoji перекрывает в обе стороны), протокол метки первого кадра и платформенный спавн замеров, лёгкость `--version`, сквозные settings/set/doctor через subprocess, команды под `PYTHONIOENCODING=cp1251` (модель Windows-пайпа), исходники пакета — грамматика 3.10 и tokenize-сканер «нет литералов и слэшей в выражениях f-строк».
- Руками через pty (поддельный терминал, подача клавиш и мыши): полный цикл заставка → ввод «привет» → Enter → спиннер → пометка → `/exit`; Ctrl+C; SIGTERM посреди заставки (терминал восстановлен, выход из альтернативного экрана есть, termios вернулся в канонический режим); вторая копия на тех же данных; терминалы 20×5 и 12×6; TERM=xterm (16 цветов) и NO_COLOR (моно); `try splash` и `try render` (мышь видна в «последнем событии»).
- Синтаксис всех файлов проверен грамматикой Python 3.10 (`ast.parse(feature_version=(3,10))`) и tokenize-сканером f-строк из тестов — одной грамматики мало: лексические ограничения f-строк до 3.12 она не видит (урок раунда 2); импорты — только стандартная библиотека. `luna try measure` дополнительно прогнан под `PYTHONIOENCODING=cp1251`: старт 103 мс, память 23,1 МБ, ЦП 0,0 % — регрессий нет, вывод не падает.

## Что посмотреть руками

- `python -m luna` в настоящем терминале: заставка и минимальный экран.
- `python -m luna try render` — витрина; покликать мышью, покрутить колесо, понажимать клавиши (последнее событие — внизу).
- `python -m luna doctor`, `python -m luna settings`, `python -m luna set ui.splash off` (и обратно `on`).
- `python -m luna set ui.emoji off` и `python -m luna try render` — фазы и спиннер узким набором; обратно — `ui.emoji on`.

## Что осталось сомнительным

- **Windows проверена тимлидом частично, исполнителем — никак**: раунд 1 нашёл дрейф координат от эмодзи и два падающих теста; раунд 2 (Windows 11, Python 3.14, уже с CI в ветке) — 1 провал и 2 ошибки из трёх красных по одной причине (вывод простых команд в пайп/cp1251), падение measure на 3.10-синтаксисе f-строки и дрейф эмодзи даже с якорями: ConPTY пересобирает поток и переписывает координаты. Всё исправлено по РЕВЬЮ-01 раундов 1–2 (якоря и таблица ширин; UTF-8 в точке входа; tokenize-страховка 3.10; `ui.emoji` с auto-выключением на ConPTY-хостах и узкими фазами). Живая перепроверка витрины на ConPTY — за тимлидом, Windows Terminal — за автором. Цифры `luna try measure` на Windows тимлид снимет сам при слиянии (п. 4 раунда 2) — строка Windows в таблице намеренно без цифр исполнителя. Ввод и raw-режим через ctypes (SetConsoleMode, WaitForSingleObject + ReadConsoleInputW) по-прежнему без живой проверки.
- **macOS и Termux не проверены** — путь POSIX общий с Linux, риск в основном в определении возможностей терминала.
- В заставке восход луны — блочный диск из ячеек фона: в моно-режиме и без юникода выглядит скромно (фазы при этом честно деградируют в ASCII-набор в строке состояния).
- Старт 111 мс — до первого кадра *заставки*; на слабом железе (Termux) цифра будет другой, тамошний замер — за автором или следующей вехой.
