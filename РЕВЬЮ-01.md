## 1. Python 3.10: f-строка с `\` внутри выражения

`luna/devtools/measure.py:280` — `{'✓' if ok else '✗'}`: обратный слэш в выражении f-строки разрешён только с 3.12, на 3.10 модуль не загрузится. Вынеси символ в переменную. Поищи такое же по всему пакету.

## 2. Вывод простых команд падает в пайп на Windows

`doctor`, `settings`, `measure` при выводе не в консоль (пайп, `> файл`, `subprocess` в тестах) пишут в cp1251, и ✓/✗ дают `UnicodeEncodeError`. Отсюда все 3 красных теста. Лечение — в начале `main()` для **всех** команд: `sys.stdout`/`sys.stderr` → `reconfigure(encoding="utf-8", errors="replace")`. Тест: команда запускается через `subprocess` с `PYTHONIOENCODING=cp1251` и не падает.

## 3. Эмодзи: якоря не помогают, нужен запасной путь

Витрина на ConPTY (терминал панели — xterm.js поверх ConPTY, как во встроенном терминале VS Code): спиннер всё так же рисуется правее, чем нужно, теперь на ~21 колонку. Закономерность: **сдвиг ≈ 1 клетка на каждый эмодзи на всём экране** (было 11 эмодзи → 10, стало 20 → 21). То есть ConPTY сам пересобирает поток для терминала, считая эмодзи шириной 1, а терминал рисует их шириной 2; наши абсолютные координаты он переписывает. Из Луны это не лечится.

Решение тимлида:
- Новая настройка `ui.emoji` (auto / on / off). `auto`: **выключено на Windows без `WT_SESSION`** (ConPTY-хосты: VS Code, сторонние терминалы, старая консоль), включено в Windows Terminal и на POSIX.
- Без эмодзи — **узкий набор фаз** шириной 1 (например `○ ◔ ◑ ◕ ●` или подбери лучше; проверь, что `east_asian_width` у них не `W`), а не только ASCII-`[##..]`. ASCII остаётся для `ui.unicode = off`.
- Все эмодзи в интерфейсе (заставка, витрина, 🚀 в образце ширины) идут через эту настройку.
- `luna doctor` показывает, включены ли эмодзи и почему.
- Якоря после широких символов оставь — они не мешают.

Проверю витрину на ConPTY ещё раз; в Windows Terminal посмотрит автор.
