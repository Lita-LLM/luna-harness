# Контракт событий агента (v1)

31.10.2026, тимлид. Единственная граница между ядром агента и клиентами (TUI, headless, позже веб/телефон/Бендер). Ядро публикует события на шину, клиент шлёт команды. Всё — JSON-совместимые словари с полем `type`; у каждого события есть `session` (id сессии) и `ts` (время, секунды). Поля только добавляются, никогда не переименовываются; незнакомые поля и типы клиент молча пропускает.

## События (ядро → клиент)

| type | поля | смысл |
|---|---|---|
| `session.start` | `cwd`, `model`, `mode` | сессия открыта |
| `turn.start` | `turn` | агент начал ход |
| `agent.thinking` | `text` | кусок рассуждения (стрим) |
| `agent.text` | `text` | кусок ответа (стрим) |
| `agent.text.done` | — | ответ этого шага закончен |
| `tool.call` | `id`, `name`, `args`, `intent` | агент вызывает тул; `intent` — его фраза «что и зачем» |
| `tool.output` | `id`, `text` | кусок вывода долгого тула (стрим) |
| `tool.result` | `id`, `ok`, `summary`, `output` | итог тула; `output` уже обрезан для показа |
| `guard.ask` | `id`, `tool`, `args`, `intent`, `risk`, `reason`, `choices` | нужно решение человека |
| `guard.verdict` | `id`, `decision`, `by`, `reason` | решение Предохранителя (`by`: rules / guard_model / human / mode) |
| `ask.user` | `id`, `question`, `options` | агент спрашивает человека (`options` может быть пустым) |
| `todo` | `items[]` (`text`, `status`) | план агента целиком |
| `usage` | `model`, `input`, `output`, `cost`, `context_pct` | расход; `context_pct` — для фазы луны |
| `mode.changed` | `mode` | режим сменился |
| `turn.done` | `turn`, `reason` | ход окончен (`end`, `interrupted`, `limit`, `error`) |
| `error` | `message`, `detail` | понятная ошибка (HumanError) |
| `notice` | `level`, `text` | служебное сообщение для человека |
| `btw.answer` | `text` | ответ на команду `btw` (вопрос в сторону): история и ход не тронуты (ЗАДАЧА-18) |
| `thinking.summary` | `text`, `seconds` | пересказ рассуждений одной строкой от роли fast (ЗАДАЧА-19): публикуется раз в `ui.thinking_summary_s` секунд раздумья и по концу размышления шага из отдельного потока; основной стрим не задерживает; `seconds` — сколько модель думала к моменту пересказа |
| `effort.note` | `model`, `text` | роутер подвинул усилие рассуждений к ближайшему допустимому для провайдера (ЗАДАЧА-19): не ошибка, место — «Обратная сторона», а не лента |
| `settings.changed` | `key`, `value`, `old`, `layer` | настройка изменилась: `layer` — global / project (запись через `luna set` или тул luna) или file (файл поправили снаружи, горячая перезагрузка) |
| `session.rewound` | `turn`, `scope`, `files` | откат выполнен: состояние после хода `turn`; `scope` — files / talk / both, `files` — сколько файлов возвращено |
| `context.compacted` | `before_pct`, `after_pct`, `before_messages`, `after_messages`, `summarized_turns` | «прилив»: старые ходы заменены сводкой быстрой модели; проценты — оценка до/после |
| `nibbler.say` | `text`, `severity`, `to`, `trigger` | реплика Ниблера — компаньона-наблюдателя; `severity`: `minor` / `serious`, `to`: `human` (только человеку) / `agent` (уйдёт агенту пометкой в следующий ход), `trigger` — повод |
| `agent.spawn` | `agent_id`, `parent_id`, `kind`, `name`, `role`, `model`, `mode`, `leader`, `notes` | ребёнок создан хозяином (ЗАДАЧА-11, docs/РОЙ.md §9); `kind`: `assistant` / `satellite` (позже `cell`); все события ребёнка дальше несут те же `agent_id`, `parent_id`, `kind`, `name` |
| `agent.state` | `agent_id`, `parent_id`, `kind`, `name`, `state` | состояние ребёнка: думает / действует / ждёт / спит / сдал / упал |
| `agent.message` | `agent_id` (получатель), `from`, `to`, `from_id`, `to_id`, `text` | письмо между агентами по правилам родителя (РОЙ.md §3); письмо будит спящего спутника; письмо хозяину уйдёт ему пометкой «[Почта команды]» в следующий ход |
| `agent.done` | `agent_id`, `parent_id`, `kind`, `name`, `summary`, `tokens`, `cost`, `budget_out?`, `dismissed?` | ребёнок сдал работу (ассистент — всегда; спутник — при роспуске или остановке бюджетом); хозяину уходит `summary`, не весь лог |
| `budget.update` | `agent_id`, `spent_usd`, `limit_usd`, `remaining_usd`, `tokens`, `rate_per_min_usd`, `eta_sec`, `forecast_min_usd`, `exhausted` | общий кошелёк детей сессии после траты ребёнка; прогноз — по текущему темпу (сколько сгорит ещё за минуту и когда кончится лимит) |
| `swarm.start` | `swarm`, `stream`, `total`, `links`, `profiles`, `budget_usd`, `mail`, `dir`, `host` | Звездопад запущен (ЗАДАЧА-15, РОЙ.md §9): поток по метеорному календарю, `host` — адрес хозяина (`leo/0`), смета предшествует событию ответом тула estimate |
| `swarm.progress` | `swarm`, `stream`, `done`, `failed`, `skipped`, `total`, `spent_usd`, `eta_sec`, `host` | ход роя: сколько сдали/упали, деньги, прогноз остатка времени по фактической скорости |
| `swarm.cells` | `swarm`, `cells`, `links` | состояния для «Созвездия»: `cells` — пары [адрес, состояние] (wait/run/done/failed/skipped); при `links: true` — агрегаты по звеньям [адрес звеньевого, состояние, сдано, всего] |
| `swarm.done` | `swarm`, `stream`, `done`, `failed`, `skipped`, `total`, `spent_usd`, `tokens`, `seconds`, `dir`, `stopped_reason`, `host` | поток завершён или остановлен; полная сводка — в `summary.md` папки потока, матери уходит короткая сводка тулом |
| `swarm.pool` | `swarm`, `stream`, `url`, `action` (`disabled`), `reason` | адрес пула выведен из пула (ЗАДАЧА-21): 401/403 от адреса или нет ключа в сейфе по имени `pool:<имя>`; повторов на этом адресе не будет, остальные адреса продолжают |

Записи журнала сессии (не события): `swarm` — `{swarm, dir, finished, total?}` пишет тул starfall при старте и в конце потока; по ней `--continue` предлагает докрутить незаконченный поток (результаты лежат в папке потока на диске).

## Команды (клиент → ядро)

| type | поля | смысл |
|---|---|---|
| `user.message` | `text`, `attachments[]`, `delivery?` | сообщение; во время хода поведение задаёт `delivery` (ЗАДАЧА-18): `inject` — подмешать в текущий ход перед следующим вызовом модели (по умолчанию; раньше так работала очередь агента), `queue` — отдельным ходом после текущего, `interrupt` — прервать ход и сразу отправить это сообщение новым ходом. Без поля — `inject` |
| `btw` | `text` | вопрос в сторону (ЗАДАЧА-18): ядро отвечает по копии текущей истории отдельным вызовом модели; историю не меняет, ходом не считается, расход честно идёт в `usage`; ответ — событие `btw.answer` |
| `interrupt` | — | прервать ход (Esc Esc); набранное, если есть, уходит следом |
| `guard.answer` | `id`, `decision`, `args?` | `yes` / `no` / `edit` (с новыми `args`) / `always` (дальше без вопросов на этом уровне) / `stop` (отменить весь ход) |
| `user.answer` | `id`, `text` | ответ на `ask.user` |
| `mode.set` | `mode` | `normal` / `plan` / `review` / `auto` / `yolo` |
| `shell` | `command` | `!команда` мимо модели |
| `undo` | — | откатить последний ход целиком (файлы и разговор) |
| `rewind` | `turn?`, `scope?` | без `turn` — список ходов; с `turn` — откат к состоянию после этого хода; `scope`: files / talk / both |
| `redo` | — | вернуть последний откат (хотя бы на шаг) |
| `compact` | `hint?` | сжать контекст сейчас; `hint` — что сохранить в сводке особенно |

Прерывание (ЗАДАЧА-18): команда `interrupt` рвёт всё сразу — идущий стрим модели (HTTP-клиент закрывает потоковый ответ, разбор возвращает частичный результат), процесс bash со всем деревом детей, ожидания guard/ask, детей и рой. Частичный ответ остаётся в истории с пометкой «[ответ прерван человеком]», вызовы тулов из оборванного шага не выполняются, причина `turn.done` — `interrupted`. В чате прерывание — Esc одним нажатием или Ctrl+C во время хода; режим доставки сообщений во время хода — настройка `chat.send_mode`, на лету — Ctrl+S, разово прервать и отправить — Alt+Enter.

Фальшивый источник событий для клиентов без настоящего агента — `luna/devtools/fake_agent.py` (появится в ЗАДАЧА-05).

## Записи журнала сессии

Журнал (`luna/core/sessions.py`) пишет записи видов `meta`, `event`, `command`, `resume`. ЗАДАЧА-13 добавила свои виды (существующие не менялись):

| kind | data | смысл |
|---|---|---|
| `rewind` | `to_turn`, `from_turn`, `scope`, `files`, `skipped` | откат выполнен; продолжение восстанавливает уже откатанное состояние |
| `redo` | `turn`, `scope`, `files` | откат возвращён |
| `compact` | `before_pct`, `after_pct`, `summary`, `summarized_turns`, `kept_turns` | «прилив»: текст сводки лежит здесь — продолжение подхватывает сжатую историю |
| `crew` | `members[]` (`name`, `role`, `prompt`, `model`, `mode`, `worktree`, `can_spawn`, `leader`, `history`) | снимок спутников сессии (ЗАДАЧА-11): состав + история каждого; продолжение (`--continue`) возвращает их спящими по последней такой записи |

## Дополнения ЗАДАЧИ-20

Команда `guard.answer` получила два новых решения (поле `decision`, существующие не менялись):

| `decision` | поля | смысл |
|---|---|---|
| `always_project` | — | «да, и больше не спрашивать для такого в этом проекте»: ранг риска запоминается в проектные настройки (`guard.always_rank_project`) и действует во всех сессиях проекта. Необратимое и секреты (hard_block) этим не обходятся — как и сессионным `always` |
| `no_replace` | `text` | «нет, и вот что вместо»: отказ, текст человека уходит модели причиной отказа и инструкцией, что делать вместо |

Роутер при сетевой недоступности публикует событие вида `retry` через `on_event` вызова `Router.chat` (текст — «Сеть или провайдер недоступны (…). Повтор через N с — попытка K из M.»); цикл агента показывает его заметкой в ленте, а не текстом ответа. Настройки повторов — `net.retry_attempts`, `net.retry_delay_s` (задержка удваивается с каждой попыткой); исчерпание попыток ведёт к следующему резервному кандидату, как раньше.
