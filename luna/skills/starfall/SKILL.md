# Рой (Звездопад): как пользоваться

## Сначала выбери инструмент

- **Одна целая задача** (исследовать, починить, написать, разобраться) — тул
  `assistant`: временный полноценный агент, сдаёт одну сводку.
- **Постоянная команда ролей** на всю сессию (ревьюер, тестер, писатель —
  живут, переписываются, помнят роли) — тул `crew`.
- **Много однотипных входов** — тул `starfall` (этот скилл): одна одноразовая
  ячейка на каждый вход, один шаблон задания на всех. Примеры: классифицировать
  40 файлов, выжать суть из 200 строк лога, перевести 15 одинаковых карточек.

Рой на 1–2 входа не запускается (настройка `starfall.min_inputs`, по умолчанию
3): пара входов дешевле сделать самой или через `assistant`. Если человек
**явно настоял** именно на рое — повтори вызов с `force: true`. Сама не
настаивай.

## Порядок запуска: смета → запуск

1. `starfall` с `action: "estimate"` — пробный прогон на 3 входах: цена и время
   одного входа и итог на все. Ничего не меняет, подтверждения не требует.
2. Покажи смету человеку как есть.
3. `starfall` с `action: "run"` и **той же сметой текстом в поле `estimate`** —
   запуск одним действием; подтверждение человеку покажет смету, профили и
   режим записи.

Пример пары вызовов:

```json
{"action": "estimate", "profile": "cls",
 "inputs": {"glob": "src/*.py"},
 "template": "Классифицируй файл одним словом: баг, фича или рефакторинг.\n{input}"}
{"action": "run", "profile": "cls",
 "inputs": {"glob": "src/*.py"},
 "template": "Классифицируй файл одним словом: баг, фича или рефакторинг.\n{input}",
 "estimate": "<текст сметы из шага 1>"}
```

## Входы (поле inputs)

- Список строк: `["первый", "второй", "третий"]` — каждый элемент — вход.
- `{"glob": "src/*.py"}` — содержимое каждого файла по маске (от текущего
  каталога) — отдельный вход.
- `{"file_lines": "задачи.txt"}` — каждая строка файла — вход.
- `{"file": "док.md"}` — весь файл — один вход.
- `{"text": "длинный текст", "chunk_chars": 2000}` — текст кусками по N
  символов; без `chunk_chars` — одним входом.

В шаблоне `template` место входа — `{input}`. Без шаблона ячейка получает
просто текст входа.

## Профили и режимы записи

Профиль (каста) задаёт модель, тулы, лимиты и режим записи ячеек; смотреть и
править — тул `cells` (`list`, `show`, `create`, `edit`, `save`). Встроенные
касты: `cls` — классификация, `rev` — ревью, `aud` — аудит безопасности,
`sum` — выжимка, `ext` — извлечение данных, `jdg` — оценка/сравнение,
`rd` — чтение и поиск, `cod` — код в worktree звена, `th` — рассуждение
без тулов, `col` — свёртка результатов звена. Несколько каст — полем `profile` через
запятую или `profiles` списком: входы делятся между профилями поровну.

Режимы записи ячейки (`write_mode` профиля, можно перекрыть в запуске):

- `none` — только ответ текстом, файлов не трогает (по умолчанию у большинства).
- `sandbox` — пишет в свою папку ячейки внутри папки потока.
- `worktree` — пишет в git worktree своего звена.
- `project` — пишет прямо в проект. Только с `project_confirmed: true`, а его
  ставь лишь после явного «да» человека.

Почта роя (`mail`): `tree` — ячейки шлют итог своему звену, звено — сводку
хозяину (по умолчанию); `neighbors` — соседу по звену; `board` — всё на общую
доску потока; `none` — тишина. Письма самой себе у ячейки не бывает.

Потолки — настройки `starfall.*`: `max_cells`, `max_parallel`, `budget_usd`,
`ttl_s`, `max_attempts`, `output_dir`. Выше потолка не прыгнуть: потолок меняет
человек в настройках, не ты.

## Как читать итог

Ответ тула `run` — короткая сводка: сколько сдали/упали/не начаты, звеньев,
денег, токенов, времени — и папка потока. В папке:

- `summary.md` — та же сводка + сводки всех звеньев;
- `summary.json` — машинный вид (поле `link_summaries` — сводки звеньев);
- `results/<номер>.json` — результат каждого входа отдельно: статус, текст,
  ошибка, цена;
- `board.json` — при почте `board`.

Для потоков до 50 входов сводки звеньев уже лежат в ответе тула — папку без
нужды не перечитывай.

## Незаконченные потоки

- `starfall` с `action: "status"` — что не закончено.
- `action: "resume"` (можно с полем `swarm` — id или путь папки) — докрутить:
  готовые результаты не переделываются, делаются только недостающие.

## Частые ошибки

- «Рой на N вход(а) не запускаю» — входов меньше `starfall.min_inputs`: это не
  сбой, а защита. Доделай сама, отдай `assistant` или спроси человека про
  `force: true`.
- «Не понимаю описание входов» — `inputs` не той формы; правильные формы —
  раздел «Входы» выше.
- «Режим записи project — только с подтверждением» — спроси человека и повтори
  с `project_confirmed: true`.
- Бюджет или число входов выше потолка `starfall.*` — потолок не обходится;
  скажи человеку, какой именно потолок мешает.
