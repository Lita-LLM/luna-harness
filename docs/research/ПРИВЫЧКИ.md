# Привычки эталонов: Claude Code, OpenCode, Codex CLI

Исследование к ЗАДАЧЕ-20 (01.11.2026). Источники: официальная документация
Claude Code (code.claude.com, раздел интерактивного режима и клавиш),
документация OpenCode (opencode.ai, TUI и сочетания клавиш), документация
Codex CLI (developers.openai.com/codex) и открытые справки по его клавишам.
Колонка «у Луны» — состояние на начало задачи; «итог» — что сделано здесь,
что уже было и что отложено с причиной.

## Замечания по источникам

- У Claude Code сочетание Ctrl+O в документации — просмотр транскрипта (verbose), оно же раскрывает свёрнутые строки; у Codex то же сочетание копирует последний вывод. Эталоны расходятся — Луна идёт за Claude Code, как велела задача («сомневаешься — делай как у них», первый названный эталон).
- У Claude Code `#` исторически дописывал строку в CLAUDE.md, но в актуальной официальной документации (осень 2026) `#` как особый ввод больше не значится: остались `/memory`, обычная просьба словами и автоматическая память. Луна `#` всё равно делает — так решил стартовый список тимлида, и механика честно своя (AGENTS.md проекта).
- OpenCode ранжирует `@`-поиск по частоте и свежести использования файлов (frecency); у Луны пока статический скоринг — совпадение раньше и путь короче. Разница отмечена в таблице как отложенное.
- Уведомления у Claude Code зависят от терминала: рабочий стол — только Ghostty/Kitty/iTerm2, остальным — звонок терминала (`terminal_bell`) или хук Notification. Луна повторяет терминальную часть (bell и OSC 9) и не лезет в нативные API ОС.
- Codex сверялся по официальной документации CLI и открытым справкам клавиш; часть сочетаний Codex (например, Ctrl+J — новая строка) в таблицу не попала, потому что у Луны это уже покрыто Shift+Enter и `\`+Enter.
