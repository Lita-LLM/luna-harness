# ЗАДАЧА-21 · Рой: изоляция bash, ключи пула, нагрузка, luna -p

Ветка: `zadacha-21` от main. Процесс и правила — [AGENTS.md](AGENTS.md). **Идёт параллельно с ЗАДАЧЕЙ-20**, поэтому `luna/ui/` не трогать. Если что-то нужно показать в интерфейсе, отдай это событием шины, отрисовку подключу при слиянии. Проект роя — [docs/РОЙ.md](docs/РОЙ.md).

## 1. Изоляция bash у ячеек

Сейчас режимы записи (`none / sandbox / worktree / project`) ограничивают пишущие тулы. Но bash ячейки — это обычный процесс с правами человека: в режиме `sandbox` он может писать куда угодно. Поэтому рой с bash сейчас всегда идёт с подтверждением. Нужна настоящая изоляция, чтобы его можно было отпустить.

- Бэкенды изоляции как данные. Настройка `starfall.sandbox`: `auto`, `bwrap`, `podman`, `docker`, `none`. `auto` берёт первое доступное.
  - **Linux:** bubblewrap. ФС только для чтения, папка ячейки (или worktree) на запись, свой `/tmp`, без сети по умолчанию. Сеть включает профиль ячейки полем `net: true`.
  - **Контейнер** (podman или docker), если есть: то же самое через монтирование.
  - **Windows и macOS:** честно сверь, что реально доступно без админа. Варианты: Job Object с лимитами и restricted token, Windows Sandbox, sandbox-exec. Если настоящей изоляции ФС нет — так и сказать: bash ячеек на этой платформе идёт только с подтверждением, как сейчас.
- Лимиты на процесс ячейки: время, память, число процессов. Где платформа умеет — жёстко, где не умеет — хотя бы по времени.
- **Предохранитель:** `_swarm_risk` перестаёт требовать вопрос для bash, только когда изоляция есть и проверена пробным запуском. Без изоляции всё как сейчас. `project` с bash спрашивает всегда.
- `luna doctor` показывает, какая изоляция доступна. Если bwrap или podman нет — подсказывает, как поставить.
- Тесты: выбор бэкенда на подменённом окружении. Живой тест bwrap, где он есть в CI: Ubuntu, `skipUnless`. Ячейка не может записать вне своей папки и не выходит в сеть без `net`.

## 2. Ключи для адресов пула

Пул моделей (`luna/starfall/modelpool.py`) знает только адреса. Узлы сети автора и платные адреса бывают с ключом, а ключ сейчас не передаётся.

- У адреса пула есть имя секрета: `secret: pool:<имя>`. Ключи кладёт только человек: через `luna setup` или `luna pool key <имя>` со скрытым вводом в сейф. Агенты и ячейки ключей не видят и не получают в переменных окружения.
- Заголовок авторизации по типу адреса: OpenAI-совместимый — `Authorization: Bearer`. Если адрес — провайдер из каталога роутера, взять его схему.
- Адрес без ключа работает как сейчас. 401 или 403 от адреса выводит его из пула с понятной причиной, без бесконечных повторов.
- Секреты не попадают в журналы, события и `scrub`. Это проверяется тестом.

## 3. Нагрузка как в жизни

Урок 499: CI ловит только то, что показывает фальшивый сервер. Нужен стенд роя на локальной фальшивой модели, которая ведёт себя как настоящая.

- Фальшивый OpenAI-совместимый сервер в `tests/` (`ThreadingHTTPServer`):
  - пауза до первого токена;
  - медленный стрим;
  - случайные 429 и обрывы;
  - ограничение параллельности по адресу.
- Сценарий: 50–70 ячеек на пуле из 3 адресов. Проверить:
  - пул делит параллельность по 429 и восстанавливается;
  - прерывание роя гасит все ячейки быстро, лимит заложить в тест, например 3 с;
  - нет утечки потоков и открытых сокетов после роя;
  - память и ЦП разумные.
- Тест быстрый, до ~30 с, с пометкой, что он нагрузочный.
- Цифры (сколько ячеек, время, пиковые потоки) записать в летопись.

## 4. Режим без экрана: `luna -p`

Нужен тимлиду: он проверяет Луну на Windows сам, но водить полноэкранный чат не может. Это и привычка из Claude Code (`claude -p`).

- `luna -p "промпт"`: один ход (или до конца работы агента), без интерфейса.
  - Ответ — в stdout, ход — в stderr: тулы, спутники, рой, кратко, по строке на событие.
  - Код выхода: 0 — успех, иначе ошибка.
  - Промпт можно передать и в stdin.
- **Флаги.**
  - `--continue` / `--resume <id>` продолжают сессию;
  - `--mode` задаёт режим Предохранителя;
  - `--output json` и `--output stream-json` выдают события шины построчно;
  - `--max-usd` и `--max-turns` — потолки.
- **Вопросы Предохранителя.** Без человека ответить некому, поэтому всё, что требует подтверждения, отклоняется с понятной причиной в stderr. Разрешить можно только явно: флагом `--allow <шаблон>` от человека или его настройками. `hard_block` не разрешается ничем.
- Тесты на фальшивой модели: ход, тул, отказ без подтверждения, json-поток, продолжение сессии.
