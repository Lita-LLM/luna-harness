# Работник в клетке: `luna -p --worker`

Клетка — точный эфемерный запуск Луны для внешних агентов: «собери за сегодня новости про X одной фразой» → ответ в stdout и код выхода. Луна в клетке видит только то, что разрешил хозяин в профиле; всё остальное закрыто (deny-by-default).

## Что клетка гарантирует

- **Только разрешённые тулы.** Модель видит лишь тулы из `tools` и MCP-тулы из `mcp.servers`; `deny` сильнее всего. Тулы `assistant`, `crew`, `starfall`, `cells`, `luna`, `manner`, `skill` в клетке не бывают никогда.
- **Только хозяйская конфигурация.** Проектный `.luna/settings.json` не читается, профили ищутся только в `LUNA_HOME/workers/` (папка проекта не сканируется), инструкции проекта (AGENTS.md и т.п.) — только при `instructions: project|all`.
- **Предохранитель не выключается.** `guard.enabled=false` в клетке не действует; жёсткие блоки (`hard_block`) не перебивает ничто, даже `allow`.
- **Файлы и сеть по спискам.** `fs: none` — файлов нет вовсе; `ro`/`rw` — только внутри `roots`, а сейф Луны, `~/.ssh`, `~/.claude` и подобное закрыты даже внутри корня. `web_fetch` ходит только на `net.fetch_hosts`, без `?параметров` (если не `fetch_query: true`), и не в локальную сеть.
- **Секреты по именам.** MCP-конфиг получает через `{{secret:…}}` только имена из `secrets`; bash (если он `sandbox`) — без ключей API в окружении.
- **Потолки.** Деньги, токены, шаги, время — из `limits`; флаги могут только уменьшить их. Деньги считаются по `model.price_in/price_out` хозяина: без цен стоимость $0, Луна предупредит в stderr — тогда держи `max_tokens`.
- **Ответы хозяина в чате не проходят внутрь.** «Больше не спрашивать» (сессия, проект) и `allow`-строки `guard.rules` в клетке не действуют; `deny`/`ask` из `guard.rules` — действуют. Единственный пропуск — `allow` профиля.
- **Без следов.** `ephemeral: true` (по умолчанию) — журнал сессии не пишется, `--continue`/`--resume` запрещены, временные папки убираются в конце.

## Чего клетка НЕ гарантирует

- **MCP-сервер делает что хочет внутри себя.** Луна решает, какие его тулы видны модели, но не знает, что сервер творит при вызове «безобидного» `get_messages` (пометить прочитанным, подгрузить медиа, что-то записать). Для Telegram-юзербота — **отдельный аккаунт только для чтения и/или сервер, у которого опасных тулов нет вовсе.** Списки `tools`/`deny` — вторая линия обороны, не первая.
- **Содержимое ответа.** Модель может ошибиться или пересказать прочитанное (в том числе чужие сообщения) — ответ уходит вызывающему агенту как есть.
- **Поиск.** `web_search` идёт через провайдера поиска хозяина; запрос модели виден этому провайдеру.
- **Путь адреса.** `fetch_query: false` запрещает `?параметры`, но данные можно спрятать в путь (`https://разрешённый.сайт/<данные>`) — их увидит владелец сайта. Держи `fetch_hosts` узким: только сайты, которым веришь.
- **Изоляция bash на Windows/macOS.** `bash: sandbox` честно изолирует только там, где есть бэкенд (bwrap/podman/docker); без него Предохранитель спрашивает, а в headless спрашивать некого — отказ.

## Профиль

Файл `LUNA_HOME/workers/<имя>.json`, строгий JSON. **Незнакомый ключ, повтор ключа, не тот тип — ошибка** (код 2): опечатка не должна молча снять лимит или запрет. Не указанное поле — самое строгое значение.

```json
{
  "version": 1,
  "description": "Новости по теме одной фразой",
  "prompt_file": "news.prompt.md",
  "model": "fast",
  "mode": "normal",
  "tools": ["web_search", "web_fetch"],
  "deny": ["mcp__*__send_*"],
  "allow": ["mcp__tg__*"],
  "mcp": {
    "config": "news.mcp.json",
    "servers": {
      "tg": {"tools": ["search_messages", "get_*"], "deny": ["send_*", "delete_*"], "required": true}
    }
  },
  "secrets": ["tg_session"],
  "fs": {"mode": "none", "roots": []},
  "bash": "off",
  "net": {"fetch_hosts": ["*.ria.ru", "t.me"], "fetch_query": false},
  "instructions": "none",
  "limits": {"max_usd": 0.3, "max_steps": 20, "timeout_s": 180},
  "output": {
    "schema": {"type": "object", "required": ["summary"], "properties": {"summary": {"type": "string"}}},
    "retries": 1
  },
  "ephemeral": true,
  "fail_on_deny": false
}
```

| Ключ | Что значит | По умолчанию |
|---|---|---|
| `version` | только `1`, обязателен | — |
| `prompt` / `prompt_file` | инструкции работника; файл — от папки профиля; что-то одно | пусто |
| `model`, `mode` | модель (роль или `провайдер:модель`) и режим `plan\|normal\|review\|auto\|yolo` | основная, `normal` |
| `tools` | встроенные тулы, шаблоны fnmatch; `mcp__…` сюда нельзя | ничего |
| `deny` | шаблоны по любым именам, включая `mcp__сервер__тул`; сильнее всего | — |
| `allow` | авто-«да» на вопросы Предохранителя: `тул` или `тул:поле=шаблон` (например `mcp__tg__send_message:chat_id=@my_channel`). Подстрока без `поле=` в клетке — ошибка: модель вписала бы её в текст письма в чужой чат | — |
| `mcp.config` | свой файл серверов (от папки профиля) вместо `LUNA_HOME/mcp.json` | общий |
| `mcp.servers.<имя>` | `tools` (сырые имена тулов сервера, шаблоны), `deny`, `required` (не поднялся — код 6) | серверов нет |
| `mcp.servers.<имя>.args` | ограничение аргументов: `{"тул": {"поле": ["значение", "@шаблон_*"]}}`. Вызов проходит, только если поле есть и все его значения (у списка — каждое) совпали; иначе отказ клетки. Так «читать сообщения» привязывается к чатам из списка, а не ко всем | без ограничений |
| `secrets` | имена секретов, доступные MCP-конфигу | — |
| `fs.mode`, `fs.roots` | `none\|ro\|rw`; корни от рабочей папки (`--cwd`), `.` — она сама, должны существовать; корень, накрывающий домашнюю папку или `LUNA_HOME`, — ошибка | `none` |
| `bash` | `off\|sandbox` | `off` |
| `net.fetch_hosts` | шаблоны хостов для `web_fetch`; `null` — любой публичный | никакие |
| `net.fetch_query` | можно ли `?параметры` в адресе | `false` |
| `instructions` | `none\|project\|all` — подмешивать ли инструкции проекта | `none` |
| `limits` | `max_usd`, `max_steps`, `timeout_s`, `max_tokens` (вход+выход за запуск); `0` — без потолка; только конечные числа | без потолка |
| `output.schema`, `output.retries` | JSON Schema ответа и сколько раз просить исправить (0–5) | нет, 1 |
| `ephemeral` | не писать журнал сессии | `true` |
| `fail_on_deny` | первый отказ Предохранителя — сразу код 4 | `false` |

Противоречия — тоже ошибка: `read` при `fs: none`, `write`/`edit` при `ro`, `bash` в `tools` при `bash: off`, `ro` без корней.

## Запуск и флаги

```
luna -p --worker news "Что нового про X сегодня? Одной фразой."
luna -p --worker-file ./my.json --output json "…"
luna -p --worker news --check            # итоговая клетка, без модели
```

Флаги `luna -p`:

| Флаг | Что делает |
|---|---|
| `--worker ИМЯ` / `--worker-file PATH` | `--worker` — только имя из `LUNA_HOME/workers/` (`news` или `news.json`), путь — только через `--worker-file` |
| `--check` | напечатать итоговую клетку (JSON) с реально видимыми тулами и ошибками MCP; код 0, модель не зовётся |
| `--tools a,b` | встроенные тулы |
| `--deny ШАБЛОН` | запрет (повторяемый) |
| `--allow ШАБЛОН` | авто-«да» Предохранителя (повторяемый) |
| `--mcp СЕРВЕР[:тул,шаблон*]` | MCP-сервер и его тулы (повторяемый) |
| `--mcp-config FILE` | файл MCP-серверов (только для клетки из флагов) |
| `--fs none\|ro\|rw`, `--root DIR` | файлы и корни (повторяемый `--root`) |
| `--bash off\|sandbox` | bash |
| `--fetch-host ШАБЛОН`, `--fetch-any`, `--fetch-query` | сеть для `web_fetch` |
| `--instructions none\|project\|all` | инструкции проекта |
| `--schema FILE` | JSON Schema ответа |
| `--timeout SEC`, `--max-usd N`, `--max-turns N`, `--max-tokens N` | потолки времени, денег, шагов, токенов |
| `--fail-on-deny` | отказ Предохранителя → код 4 |
| `--mode`, `--model` | режим и модель |
| `--cwd DIR` | рабочая папка запуска |
| `--output text\|json\|stream-json` | формат вывода |

**Три способа:**
- `--worker`/`--worker-file` — профиль, флаги его **сужают**;
- без профиля, но с любым флагом клетки (`--tools`, `--deny`, `--mcp`, `--mcp-config`, `--fs`, `--root`, `--bash`, `--fetch-*`, `--instructions`) — **разовая клетка из одних флагов**: что не названо — закрыто; `--fs ro` без `--root` — только рабочая папка; названный `--mcp` сервер обязателен; секретов у такой клетки нет (нужны — пиши профиль);
- без всего этого — обычная полная Луна, как раньше.

`--timeout`, `--schema`, `--fail-on-deny` работают и без клетки.

### Правила сужения

Флаги никогда не расширяют профиль:
- `tools`, `--mcp сервер:тулы`, `--fetch-host` — пересечение с профилем (сомнительное пересечение шаблонов — выкидывается);
- `deny`, `allow` — добавляются (`allow` действует лишь на уже видимые тулы и не перебивает `hard_block`);
- лимиты — меньший из ненулевых;
- режим — строже из двух (`plan` < `normal` < `review` < `auto` < `yolo`), молча;
- `--root` — только внутри корней профиля;
- схема флагом — только если в профиле её нет;
- **явная попытка расширить** (`--fs rw` при `ro`, `--bash sandbox` при `off`, `--fetch-any`/`--fetch-query` сверх профиля, сервер не из профиля, `--instructions` шире, `--mcp-config`) — ошибка, код 2.

## Вывод

- `--output text` (по умолчанию) — в клетке в stdout только **итоговый ответ** (последний шаг; при схеме — сам JSON-объект), ход — в stderr.
- `--output json` — **один объект** в stdout в самом конце (и в клетке, и без неё):

```json
{"status": "ok", "result": "текст ответа", "structured": {"summary": "…"},
 "cost_usd": 0.0123, "steps": 3, "tools_used": ["web_search", "mcp__tg__search_messages"],
 "denials": [{"tool": "mcp__tg__send_message", "reason": "…"}],
 "error": null, "worker": "news"}
```

`status`: `ok | error | limit | denied | schema | mcp | interrupted`; `structured` — разобранный JSON, если есть схема и он прошёл.
- `--output stream-json` (и старый `--json`) — события шины построчно, как в [СОБЫТИЯ.md](СОБЫТИЯ.md).

Схема: ответ должен быть ровно JSON-объектом (допустима обёртка ` ```json `). Не прошёл — Луна шлёт тому же агенту список ошибок и просит исправить, до `output.retries` раз; потом код 5.

## Коды выхода (любой `luna -p`)

| Код | Что |
|---|---|
| 0 | готово |
| 1 | ошибка модели или сети |
| 2 | флаги, настройки, профиль (в т.ч. `--continue`/`--resume` в клетке) |
| 3 | потолок: шаги, деньги или время |
| 4 | отказ Предохранителя при `fail_on_deny` |
| 5 | ответ не прошёл схему |
| 6 | обязательный MCP-сервер не поднялся |
| 130 | прервано (Ctrl+C) |

## Доверенные проекты: `luna trust`

```
luna trust [ПАПКА]      пометить проект доверенным (без папки — текущая)
luna trust --list       список
luna untrust [ПАПКА]    снять доверие
```

Список живёт только в глобальных настройках (`security.trusted_projects`) — проект не может довериться сам. У доверенного проекта `.luna/settings.json` действует целиком, у остальных он защиту только сужает. **Клетку доверие не касается:** проектный слой работник не читает никогда.

## Как потрогать

```
luna -p --tools web_search --check
luna -p --tools web_search --output json "Курс биткоина одной фразой"
```
