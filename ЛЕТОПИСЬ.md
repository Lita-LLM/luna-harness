## 31.10.2026 · Исполнитель (Muse Spark) · ЗАДАЧА-01: каркас и рендерер, веха 0 закрыта

**Просил автор:** через тимлида — выполнить ЗАДАЧА-01 в ветке `zadacha-01`: фундамент Луны без агента и моделей.

**Сделано:** пакет `luna/` на Python 3.10+ без сторонних пакетов. Ядро перенесено из Бендера (шина, HumanError, ULID, даты, пути, pathutil, fsutil, json5, run_lock; в каждом модуле строка-источник с коммитом Бендера). Настройки — компактная схема со слоями (умолчания → `~/.luna/settings.json` → `./.luna/settings.json`), незнакомые поля сохраняются, изменение публикует `settings.changed`. Свой терминальный рендерер: буфер ячеек и дифф одной записью на кадр, градиенты и деградация truecolor→256→16→mono, ширина CJK/эмодзи, ввод с мышью SGR 1006 и bracketed paste, планировщик анимаций без опросов (в простое — блокирующее ожидание ввода). Заставка с восходом луны и временем старта в углу, минимальный экран (эхо, спиннер по Enter, фаза луны в строке состояния), экран общается только через шину. `luna doctor`, `luna settings`, `luna set`, `luna try render|splash|measure`. Итог вехи — ВЕХА-0.md.

**Замеры (эта ВМ, pty 80×24):** старт до первого кадра — медиана 111 мс из 7 запусков (цель ≤ 200), память в простое 22,9 МБ (цель ≤ 40), ЦП в простое 0,0 % за 10 с, пакет — 0,13 МБ.

**Узнали:** дифф-рендерер и блокирующий ввод дают честный 0 % ЦП без всяких ухищрений — главное не тикать «на всякий случай» ради часов в строке состояния (они обновляются по кадрам, а не по таймеру). tty.setraw на POSIX гасит OPOST — вернули постобработку вывода, иначе обычный print после raw ломался бы. Затирание половины широкого символа должно стирать его целиком, это теперь закреплено тестом.

**Решили:** настройки bool в файлах — настоящие true/false, а on/off — только представление в CLI. Windows-путь ввода и метрик написан на ctypes, но без живой Windows не считается проверенным: `try measure` там честно отказывает (нужен ConPTY).

**Где остановились:** веха 0 выполнена полностью по чеклисту, кроме живой проверки на Windows/macOS/Termux и старой консоли Windows — железа не было. Тесты: 37, зелёные.

**Что дальше:** веха 1 по плану (цикл агента, провайдеры, роутер — перенос из Бендера по карте). Файл ЗАДАЧА-01-каркас.md удалён в этой ветке.

### Для постановщика следующей задачи

- Что вышло хуже: луна на заставке — блочный диск из фоновых ячеек; красиво в truecolor, скромно в mono/16. Если захочется «вау» — отдельная задача на полублоки (▀▄) и тень-терминатор, рендерер это уже умеет по ячейкам. В `try render` деградация показана преддеградированными цветами: на терминале уровня 256 витрина уровней 16/mono всё равно пройдёт через квантование 256 — для честной картинки нужен запуск с `luna set ui.color 16`.
- Что не проверено вживую: Windows (терминал, ввод, старая консоль), macOS, Termux; замер старта на слабом железе; мышь в tmux/screen (SGR 1006 обычно пробрасывается, но руками не гонял).
- Что ждёт автора: посмотреть заставку глазами в настоящем терминале (pty-прогон не передаёт красоту) и решить, оставлять ли время старта в углу заставки навсегда. Приёмка вехи и слияние — за тимлидом.
- Дальше по коду: цикл ввода в `ui/app.py` и `ui/render_try.py` дублируется (события → шина → состояние → кадр) — перед вехой 2 с панелями стоит вынести общий `run_screen`-цикл. Настройки уже шлют `settings.changed` — горячая перезагрузка вехи 4 просто подпишется.
- Как потрогать: `python -m luna` · `python -m luna try render` · `python -m luna try measure` · `python -m unittest -q`.

**Заметки на полях:** окружение исполнителя — Linux-ВМ без живого TTY: интерактив проверялся pty-прогонами с подачей клавиш, мыши и сигналов (SIGTERM посреди заставки, Ctrl+C, вторая копия). Секреты не читались. Коммиты ветки: каркас и ядро; рендерер; doctor и measure; тесты и правки по ревью; эта запись.
